## 工作记录 2（12:38）— 架构修复升级

### 背景
依据可行性验证结论，项目定位与架构需要一次正式修复。

### 核心变更
| 项 | 变更前 | 变更后 |
|----|--------|--------|
| 项目定位 | AI猫无人直播系统 | AI互动宠物直播引擎 |
| 架构层数 | 5 层 | **7 层**（新增平台接入层、事件网关层） |
| 事件入口 | 按钮直连业务逻辑 | 事件模拟器 → Gateway → Engine |
| 阶段划分 | Phase 0~5（按技术模块） | **Phase 1~4（按验证目标）** |
| 平台接入 | 模糊，放在最后 | 拆为 Phase 3（准备+Go/No-Go）+ Phase 4（接入） |

### 7 层架构（权威定义）
1. **Platform Adapter Layer** — 平台接入层（Simulator/Douyin/YY/Bilibili）
2. **Event Gateway** — 事件网关层（统一格式归一化）
3. **Interaction Engine** — 互动引擎（规则匹配 + 优先级）
4. **Action Engine** — 动作系统（状态机 + 队列 + idle恢复）
5. **Playback Manager** — 播放控制层（异常降级不中断）
6. **Asset Manager** — 素材管理层（禁止硬编码角色名）
7. **Data Manager** — 数据层（pets/actions/events/interactions/users）

### 新增架构红线
- C1 业务逻辑禁止依赖具体平台
- C2 平台替换不得修改核心业务
- C3 禁止硬编码角色名
- C4 播放失败不得中断系统
- C5 禁止未经授权的数据抓取（**新增，合规底线**）
- C6 直播展示须标明 AI 生成属性（**新增，合规底线**）
